# Прокси и исключения в профиле

В профиле Easyaller можно сохранить адрес прокси и список исключений вместе с уже существующим режимом прокси `promptAtRuntime`. Оба поля — данные профиля, поэтому перед экспортом они отмечаются как конфиденциальные.

English version: [PROXY_BYPASS.md](PROXY_BYPASS.md).

## Контракт профиля

Поле `machine.proxy.bypassList` необязательно и допускается только при `machine.proxy.mode` со значением `promptAtRuntime`.

- В редакторе профиля укажите до 256 значений через запятую, точку с запятой или новую строку.
- Разрешены имя хоста, IPv4-адрес, шаблон с `*`, например `*.example.test`, и документированный WinHTTP-токен `<local>`.
- Пробелы, URL, текст команд и повторяющиеся значения не допускаются.
- Адрес прокси — данные профиля, как и список исключений; он конфиденциален, но не секретен, и показывается для проверки перед экспортом. Пароль или токен программа в профиль никогда не сохраняет.

Нейтральный пример фрагмента профиля:

```json
"proxy": {
  "mode": "promptAtRuntime",
  "bypassList": ["*.example.test", "<local>", "192.0.2.53"]
}
```

## Что меняет применение

После проверки адреса прокси и явного подтверждения Windows-адаптер записывает один и тот же адрес и список исключений в два независимых хранилища прокси Windows за одну операцию:

1. **WinHTTP** — фиксированная PowerShell-команда `Set-WinhttpProxy`. Общесистемное хранилище для Windows Update и других фоновых служб. В Параметрах не отображается.
2. **WinINET** — значения `HKCU\Software\Microsoft\Windows\CurrentVersion\Internet Settings` (`ProxyEnable`, `ProxyServer`, `ProxyOverride`) текущего пользователя. Это то же хранилище, что редактируется в **Параметры → Сеть и Интернет → Прокси** и используется браузером и большинством настольных программ. Easyaller уведомляет запущенные процессы об изменении через документированный WinINET API `InternetSetOption` (`INTERNET_OPTION_SETTINGS_CHANGED` и `INTERNET_OPTION_REFRESH`), поэтому изменение действует без выхода из системы.

Эти два хранилища независимы и не синхронизируются друг с другом — поэтому оба выставляются из одного адреса в профиле. Если запись не удалась, значения WinINET в реестре откатываются к состоянию до попытки.

Настройка не означает автоматическую настройку PAC-скрипта, VPN-клиента или программы с собственным отдельным прокси. Перед применением проверьте целевые программы.

Microsoft документирует `Set-WinhttpProxy` в [модуле WinHttpProxy для PowerShell](https://learn.microsoft.com/en-us/powershell/module/winhttpproxy/set-winhttpproxy?view=windowsserver2025-ps) и `InternetSetOption` в [справочнике WinINET API](https://learn.microsoft.com/en-us/windows/win32/api/wininet/nf-wininet-internetsetoptionw). Обе команды доступны только в Windows. До использования на рабочей станции нужен результат проверки в Windows VM.

## Граница безопасности

- Easyaller не ищет адреса прокси и исключения автоматически — оператор вводит их сам или явно импортирует с текущего ПК.
- Адрес прокси и список исключений не попадают в состояние resume, хотя и хранятся в профиле.
- Поле профиля не является произвольным аргументом PowerShell или WinINET и не может нести команду.
- Предпросмотр экспорта помечает список как конфиденциальный, так как он может раскрывать структуру внутренней сети.
- Для этой возможности ещё нет проверки в Windows VM или на физическом ПК.
