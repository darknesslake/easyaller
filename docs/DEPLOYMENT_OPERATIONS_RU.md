# Эксплуатационная инструкция по развёртыванию

Это единый безопасный путь проверки развёртывания Windows с Easyaller. Программа находится в пре-альфа. Сначала работайте в изолированной виртуальной машине Windows 11, затем на выделенном тестовом ПК. Не используйте корпоративную рабочую станцию, корпоративные учётные данные или единственную копию важных данных.

English version: [DEPLOYMENT_OPERATIONS.md](DEPLOYMENT_OPERATIONS.md).

## Текущая граница возможностей

Easyaller создаёт проверенный профиль, детерминированный `autounattend.xml`, dry run в памяти, пакет с проверенными хэшами и раскладку установочного USB из Windows Setup и пакета на уже пустом отформатированном съёмном томе. Для USB нужны явный выбор подходящего съёмного диска и точная фраза `ERASE`.

Программа не скачивает, не монтирует, не изменяет и не проверяет ISO; не форматирует, не размечает и не выбирает внутренний диск; не присоединяет к домену во время Windows Setup; не применяет настройки конфиденциальности в Windows и не управляет реальной временной учётной записью. Интерфейс также не добавляет временную учётную запись, payload, установщики, скрипты или bootstrapper первого входа. Последние пути существуют только как API-контракты и требуют доказательств Windows SIM и теста в VM до использования.

## До первого теста

1. Подготовьте Windows 11 Pro или Enterprise amd64, официальный ISO от администратора, один пустой диск VM и checkpoint `before-oobe`. Для физического пилота заменяйте VM только после успешного теста VM, используйте выделенный тестовый ПК и восстанавливаемую флешку.
2. Проверьте ISO в режиме только для чтения и запишите его SHA-256, редакцию, версию, сборку и выбранный индекс образа. Следуйте [ISO_INSPECTION_RU.md](ISO_INSPECTION_RU.md) и [WINDOWS_SIM_VALIDATION_RU.md](WINDOWS_SIM_VALIDATION_RU.md).
3. В Easyaller создайте или импортируйте нейтральный профиль. Проверьте локаль, часовой пояс, параметры OOBE и совместимость. Неизвестная версия или сборка означает предупреждение, а не доказательство работоспособности.
4. Создайте dry run, экспортируйте пакет в новую папку вне Git и сохраните его `deployment-manifest.json`. Не коммитьте профили, пакеты, ISO, доказательства, пароли учётных записей или скриншоты с конфиденциальными данными.

## Подготовка установочного USB

1. Смонтируйте или распакуйте уже одобренный ISO, не изменяя его. В окне **Создать установочный USB** выберите корневой каталог Windows Setup и экспортированный пакет.
2. Подключите одну пустую, заранее отформатированную тестовую флешку. В списке видны только подходящие съёмные диски, и ни один не выбран по умолчанию.
3. Выберите носитель, создайте план, сопоставьте производителя, серийный или неизменяемый ID, номер и размер с физическим устройством, затем точно введите `ERASE`.
4. Дождитесь итоговой проверки хэшей. Статус готовности означает только совпадение записанных файлов с планом. Он не доказывает, что прошивка загрузит носитель или Windows Setup примет файл ответов.

Процесс останавливается без статуса готовности при непустом томе, смене или небезопасности диска, неоднозначной привязке буквы, изменении источника, коллизии путей, ошибке копирования или несовпадении хэша. Он никогда не форматирует и не размечает USB. Полный контракт безопасности описан в [USB_CREATOR_RU.md](USB_CREATOR_RU.md).

## Windows Setup и поиск файла ответов

Экспортированный пакет кладёт `autounattend.xml` в свой корень. После копирования пакета на установочную флешку файл находится в корне USB. Microsoft документирует поиск файла с именем `Autounattend.xml` в корне съёмного носителя, если другой файл ответов не выбран. На обычных файловых системах Windows регистр имени не важен, но Easyaller сохраняет сгенерированное имя в нижнем регистре. Во время теста не подключайте другие съёмные носители с файлами ответов.

Windows Setup можно также запустить из WinPE с явным параметром `/unattend:<path>`. Это расширенный операторский путь, интерфейс Easyaller его не запускает. См. [Automate Windows Setup](https://learn.microsoft.com/en-us/windows-hardware/manufacture/desktop/automate-windows-setup?view=windows-11) и [Windows Setup command-line options](https://learn.microsoft.com/en-us/windows-hardware/manufacture/desktop/windows-setup-command-line-options?view=windows-11).

## Безопасная установка Windows

1. Загрузите VM или тестовый ПК с готового USB в режиме UEFI.
2. На странице выбора диска вручную выберите единственный предназначенный пустой диск. Easyaller не генерирует разметку и никогда не выбирает внутренний диск.
3. Наблюдайте за всеми страницами Windows Setup и OOBE. Файл ответов содержит только явно заданные документированные настройки. При пропущенных или неверных обязательных настройках Setup может показать интерфейс. Это ожидаемое поведение, а не причина добавлять недокументированный обход.
4. Если Windows показывает страницу, которую профиль должен был автоматизировать, запишите страницу, сборку, SHA-256 ISO и подходящие журналы. Не добавляйте `BYPASSNRO`, `SkipMachineOOBE`, `SkipUserOOBE`, автоматизацию интерфейса или эмуляцию клавиш.
5. Пройдите оставшиеся страницы Windows вручную. В пилоте не присоединяйте к рабочему домену и не вводите рабочие учётные данные.

## Временная учётная запись, первый запуск и очистка

Интерфейс пока не создаёт временную локальную учётную запись. Если позже используется пакет через API, единственное поддерживаемое имя временной учётной записи - `ProvisioningAdmin`; пароль генерируется для каждого пакета, может быть показан один раз и не должен попадать в Git, доказательства или обычные журналы. `PlainText=false` в файле ответов означает обфускацию, а не шифрование.

AutoLogon намеренно отсутствует. Bootstrapper первого входа тоже не включается из интерфейса. Его путь через API требует ручного входа `ProvisioningAdmin`, payload Easyaller с проверенным manifest, проверки Windows SIM и теста в одноразовой VM. Перед включением прочитайте [FIRST_LOGON_BOOTSTRAP_RU.md](FIRST_LOGON_BOOTSTRAP_RU.md).

Очистка временной учётной записи сейчас является только моделью состояний. Она не может отключить или удалить учётную запись Windows. Будущий адаптер сможет выполнить очистку только после доказательств resume, домена при необходимости, финальной проверки и наличия административного доступа. См. [TEMPORARY_ACCOUNT_CLEANUP_RU.md](TEMPORARY_ACCOUNT_CLEANUP_RU.md).

## Доказательства, журналы и совместимость

Записывайте дату теста, модель хоста или VM, режим прошивки, SHA-256 ISO, индекс образа, редакцию, версию, сборку, ревизию профиля, хэш манифеста пакета, тип выбранного диска, показанные страницы OOBE, результат и короткое описание ошибки. Храните доказательства вне Git.

При сбое Setup сначала соберите `setuperr.log`, затем `setupact.log`. До конфигурации диска журналы Windows Setup находятся в `X:\Windows\Panther`, после неё - в `%WINDIR%\Panther`. Обработку файла ответов в OOBE также можно исследовать в `%WINDIR%\Panther\UnattendGC`. Перед передачей журналов удалите имена учётных записей, ключи продуктов, серийные идентификаторы и данные организации. Эти расположения описаны Microsoft в [Windows Setup log files and event logs](https://learn.microsoft.com/en-us/windows-hardware/manufacture/desktop/windows-setup-log-files-and-event-logs?view=windows-11).

Текущий каталог перечисляет Windows 11 24H2 build 26100 и 25H2 build 26200 для Pro и Enterprise amd64 только как документированные. Ни одна запись ещё не проверена Windows SIM или VM. См. [COMPATIBILITY.md](COMPATIBILITY.md).

## Устранение проблем

| Симптом | Безопасное действие |
| --- | --- |
| В окне USB нет диска | Убедитесь, что это съёмный USB, SD или MMC, он в сети, доступен для записи и не является системным или загрузочным. Не обходите фильтр, передавая программе букву диска. |
| Программа отклоняет корень USB | Очистите и отформатируйте выделенный тестовый том вне Easyaller, затем проверьте, что он принадлежит выбранному диску и имеет ровно один раздел с буквой. Easyaller не подготавливает носитель. |
| Не прошла проверка хэша или изменился источник | Откажитесь от неполной раскладки USB, при необходимости пересоздайте пакет и начните заново с теми же проверенными источниками. Не исправляйте файлы вручную после плана. |
| Setup не применяет ожидаемую автоматизацию | Проверьте, что подключён только один съёмный носитель с файлом ответов, `autounattend.xml` лежит в корне USB, выбранный ISO соответствует входу проверки, затем изучите Panther. |
| Setup остановился на странице OOBE | Завершите страницу вручную, сохраните доказательства и считайте цель непроверенной. Не добавляйте недокументированные обходы. |
| Неизвестная сборка показывает предупреждение | Остановите развёртывание после одноразового теста. Получите доказательства Windows SIM и VM до признания совместимости. |
| Ожидается первый вход или очистка | Это недоступно через интерфейс. Не имитируйте это самодельными скриптами или удалением учётной записи. |

## Условия перехода дальше

Не переходите к пилоту на физическом ПК, пока для точных ISO, индекса образа, файла ответов, редакции Windows, версии и сборки нет чистого результата Windows SIM и успешного запуска в изолированной VM. Физический пилот остаётся WP-062 и требует отдельных записанных доказательств.
