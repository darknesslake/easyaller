# Применение runtime-настроек

Easyaller теперь может применить runtime-значения выбранного профиля через экран **Настроить этот ПК**. Это Windows-only путь в пре-альфа. Для него есть mock-тесты и тесты модели состояний, но он ещё не запускался в Windows VM или на физическом ПК.

English version: [PROVISIONING_EXECUTION.md](PROVISIONING_EXECUTION.md).

## Явная граница

Экран сначала проверяет runtime-значения без изменений Windows. Для применения нужны точная фраза `APPLY` и права администратора. В переиспользуемом профиле по-прежнему нет пароля, токена или доменных учётных данных. Runtime-доменная учётная запись существует только в памяти для фиксированной операции domain join, маскируется строковым выводом и освобождается после операции.

Executor принимает только фиксированные операции в этом порядке:

1. Проверить, что введённому имени адаптера или interface GUID соответствует ровно один включённый сетевой адаптер. IP-адреса, DNS, Wi-Fi-данные и маршруты не назначаются.
2. Если профиль запросил прокси, установить WinHTTP proxy Windows из runtime-значения.
3. Переименовать локальный компьютер.
4. Если оператор ввёл имя домена и краткоживущие учётные данные, присоединить компьютер к этому домену.

Executor не форматирует диски, не изменяет ISO, не выбирает внутренний диск, не добавляет установщики, не исполняет команды из профиля, не применяет неуказанные настройки конфиденциальности и не придумывает сетевые настройки. Он не использует обходы OOBE.

## Применение и resume

1. Запустите Easyaller в Windows от имени администратора.
2. Выберите профиль, заполните запрошенные runtime-значения и нажмите **Проверить введённые значения**.
3. Ещё раз проверьте цель, точно введите `APPLY`, затем нажмите **Применить к Windows**.
4. Если успешно изменено имя компьютера или выполнен domain join, Easyaller сохраняет небольшое состояние resume в `%ProgramData%\Easyaller\state`. В нём есть только ID выполнения, ID и ревизия профиля, ожидаемое имя компьютера, признак запроса domain join и время создания. Пароля, прокси и имени домена там нет.
5. Easyaller пытается зарегистрировать одно фиксированное продолжение `RunOnce` для `--resume-provisioning`. Если это не удалось, перезагрузите Windows вручную и запустите Easyaller с этим аргументом. Не редактируйте файл состояния.
6. После перезагрузки resume проверяет итоговое имя компьютера и, если нужно, присоединение к домену, затем удаляет ожидающее состояние.

Windows обрабатывает системный `RunOnce` только когда после перезагрузки входит администратор. Запись ограничена командой запуска текущего Easyaller и не является универсальным запускателем команд. См. Microsoft [Run and RunOnce registry keys](https://learn.microsoft.com/en-us/windows/win32/setupapi/run-and-runonce-registry-keys).

## Документированные механизмы Windows

Windows-адаптер запускает только фиксированные команды `Rename-Computer`, `Add-Computer` и `Set-WinhttpProxy`. Значения пользователя передаются вне текста команд. Пароли не попадают в командную строку, а стандартный вывод и ошибки PowerShell не записываются. Microsoft документирует [Rename-Computer](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.management/rename-computer?view=powershell-7.6), [Add-Computer](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.management/add-computer?view=powershell-5.1) и [Set-WinhttpProxy](https://learn.microsoft.com/en-us/powershell/module/winhttpproxy/set-winhttpproxy?view=windowsserver2025-ps).

## Условия остановки

Easyaller останавливается без продолжения, если фраза подтверждения не совпала, runtime-проверка не прошла, нет Windows или прав администратора, сетевой адаптер отсутствует, отключён или неоднозначен, либо не прошла фиксированная операция. Ошибка после предыдущей операции может оставить это предыдущее изменение в Windows. Программа показывает только общий код ошибки и намеренно не выводит текст PowerShell, который может содержать данные организации.

Не используйте этот путь против рабочего домена или рабочей станции, пока WP-041 не зафиксирует Windows SIM и VM доказательства для точной целевой сборки. Первый физический запуск остаётся WP-062.
