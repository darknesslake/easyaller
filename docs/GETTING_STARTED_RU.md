# Начало работы с Easyaller

Easyaller находится на стадии пре-альфа. Сейчас программа безопасно создаёт, редактирует, проверяет, импортирует и экспортирует переиспользуемые профили компьютеров. Исходный код умеет генерировать проверенный `autounattend.xml`, но настольное приложение пока не показывает этот сценарий и не экспортирует пакет развёртывания. Программа не меняет параметры Windows и не создаёт установочный USB-накопитель.

## Запуск программы

Установите .NET SDK 10, затем клонируйте репозиторий и запустите настольное приложение Avalonia:

```sh
git clone https://github.com/darknesslake/easyaller.git
cd easyaller
dotnet run --project src/Easyaller.App/Easyaller.App.csproj
```

В текущем окружении разработки на macOS команда SDK выглядит так:

```sh
/opt/homebrew/opt/dotnet/libexec/dotnet run --project src/Easyaller.App/Easyaller.App.csproj
```

## Создание и использование профиля

1. Откройте экран **Профили** и нажмите **Новый профиль**.
2. Укажите название профиля, редакции и архитектуру Windows, локали, часовой пояс, параметры OOBE, конфиденциальности и запросы для компьютера.
3. Добавляйте приложения только как пути внутри пакета или элементы с внешней ручной установкой. Не добавляйте абсолютные пути, переходы вверх по каталогам, сырые команды, пароли, токены и доменные учётные данные.
4. Нажмите **Сохранить изменения**. Easyaller проверит профиль перед локальным сохранением.
5. Используйте **Экспорт**, чтобы создать переносимый файл `*.wpprofile.json`. Проверьте сводку конфиденциальных полей и подтвердите экспорт.
6. На другом ПК используйте **Импорт**, посмотрите результат и явно выберите действие, если профиль с тем же ID уже существует.

Профили хранятся вне репозитория: `%ProgramData%\Easyaller\Profiles` в Windows и в локальном каталоге данных текущего пользователя на других поддерживаемых настольных платформах. Локальные профили и экспортированные файлы профилей по умолчанию игнорируются Git.

## Предпросмотр будущей настройки

Откройте **Настроить этот ПК**, чтобы посмотреть план настройки для выбранного профиля. На этом экране можно проверить значения, которые вводятся только во время настройки: имя компьютера, сеть, прокси и присоединение к домену. Он пока не применяет эти значения к Windows.

Доменные учётные данные намеренно запрашиваются только во время настройки. Они не являются полями профиля и никогда не должны попадать в экспортированный профиль.

## Состояние развёртывания

В репозитории уже есть документированный каталог совместимости Windows 11, валидатор deployment-профиля и детерминированный генератор `autounattend.xml`. Dry run в памяти использует тот же генератор и показывает итоговый профиль, параметры OOBE и конфиденциальности, статус совместимости и точные байты файла ответов, ничего не записывая на диск и не меняя Windows. Файловый экспорт на уровне кода собирает пакет через staging-каталог, проверяет SHA-256 хэши и атомарно создаёт новый каталог назначения. Он предупреждает, что сведения профиля организации и обфусцированный пароль временной учётной записи являются чувствительными материалами и требуют проверки перед передачей. Генератор использует только проверенные локали, часовой пояс, явно заданные параметры OOBE и необязательную временную локальную учётную запись. Её 24-символьный пароль генерируется криптографически, может быть показан один раз, а внутренние символьные буферы очищаются после показа или освобождения объекта. Генератор не создаёт разметку диска, ключ продукта, присоединение к домену или AutoLogon.

Пока не реализованы:

- Генерация `autounattend.xml` из интерфейса программы
- Генерация или экспорт пакета развёртывания из интерфейса программы
- Скачивание или изменение ISO-образов
- Форматирование дисков и создание установочных USB-накопителей
- Присоединение к домену во время установки Windows

Документированные целевые версии Windows смотрите в [COMPATIBILITY.md](COMPATIBILITY.md), а границы продукта - в [PRODUCT_SPEC.md](../PRODUCT_SPEC.md).

Состав пакета, правила для файлов и границы проверки описаны в [DEPLOYMENT_PACKAGE_RU.md](DEPLOYMENT_PACKAGE_RU.md).

## Сборка и тесты

```sh
dotnet build Easyaller.slnx
dotnet test Easyaller.slnx --no-build
```

Запускайте эти команды перед вкладом в проект. Набор тестов проверяет строгую загрузку профилей, работу локального хранилища, безопасность импорта и экспорта, логику редактора, построение плана настройки и проверку deployment-профиля.
