# Машина состояний очистки временной учётной записи

В Easyaller появилась детерминированная in-memory машина состояний, которая решает, когда временную учётную запись provisioning можно отключить или удалить. Она не вызывает Windows API управления учётными записями, не меняет локальную учётную запись и не хранит пароли.

## Состояния

Машина состояний последовательно фиксирует применимые состояния:

1. `created`
2. `firstLogin`
3. `provisioning`
4. `domainJoined`, если поток требует присоединения к домену
5. `validated`
6. `cleanupEligible`
7. `cleaned`

Для потока без обязательного присоединения к домену состояние `domainJoined` намеренно пропускается. Его нельзя отметить в таком потоке.

## Условие очистки

Финальная проверка принимается только при наличии всех требуемых подтверждений:

- завершено resume, если deployment требует resume;
- подтверждено присоединение к домену, если deployment его требует;
- подтверждён ожидаемый административный доступ.

Только после этого состояние может стать `cleanupEligible`. Политика выбранного профиля определяет планируемое действие: `disable` или `delete`. Будущий Windows-адаптер сможет выполнить только это запланированное действие и затем сообщить `cleaned`; он не должен сам определять готовность или обходить проверку.

В модели намеренно нет запасного удаления по таймеру, после перезагрузки или при отсутствии результата проверки. До появления реального адаптера обязательны проверки Windows SIM и одноразовой VM.
